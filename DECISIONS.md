# Decisions

Choices made while setting up the project, with the reason and how to change each one.
Newest section first.

## Agents: models and workflow (2026-10-14)

| # | Decision | Why | To change |
|---|---|---|---|
| 10 | **Only free models: Ollama Cloud's free models, plus the Gemini API free tier for the reviewer.** The planned GLM, DeepSeek and Kimi models were dropped | All of them returned HTTP 402 on Ollama's free plan. Free there: `gpt-oss`, `nemotron-3`, `gemma4`. One 402 locks OpenClaw's Ollama key for ~10 minutes for every agent, so no paid model is configured even as a fallback | `agents/openclaw/openclaw.json5`, `agents/hermes/*.json`, then re-run `agents/setup.sh` |
| 11 | **The reviewer runs on `gemini-2.5-flash` (Google), with Google-only fallbacks** | It must not share a model family with the builders (`gpt-oss`, OpenAI) or the orchestrator (`nemotron`, NVIDIA). It does one run per PR, which fits Gemini's free limit of 5 requests a minute | `agents/hermes/reviewer.json` |
| 12 | **No Gemini 3.x Flash models.** Their free tier allows 20 requests a day | They also returned 503 "high demand" for hours, and failed calls count against the 20. One agent run takes 3–12 requests | Add one as a fallback in `agents/hermes/*.json` |
| 13 | **Groq is not configured for any agent** | Its free tier allows 8,000 tokens a minute, and one agent request is 12,000–28,000 tokens. Left for the app's own summaries | |
| 14 | **The prompts are copied into each runtime before every run** (`agents/sync-prompts.sh`), not symlinked | OpenClaw refuses symlinked prompt files. Copying from the `main` checkout means a prompt changes only through a merged PR | |
| 15 | **The tester runs on `gemma4:31b`, not `nemotron-3-super`** | In the smoke test (one read-only task per agent), `nemotron-3-super` ran no command and made up its answer: a commit, a PR and 17 issues that don't exist. `gemma4:31b` and `nemotron-3-ultra` both ran the commands and answered correctly; `gemma4:31b` used half the tokens. The tester and reviewer now share a family (Google), but neither shares the builders' | `agents/openclaw/openclaw.json5` |
| 16 | **No debt-lead for now.** The team is five agents: orchestrator, two builders, tester, reviewer | The brief asks for those four roles. The tech-debt sweep was an extra, and cutting it keeps the build week on the core loop. The `tech-debt` label stays, so any agent can still file one | The debt-lead's prompt, Hermes settings and dispatcher step are in git history (commit `bc4a7ca`) |
| 17 | **A third builder, builder-ops, owns getting the app running on the VM**: `scripts/install.sh` (virtualenv, dependencies, the web app's user service) and the schedule's crontab line. The team is six agents | The brief's suggested team has an optional "Ops builder" for exactly this. The install script is the riskiest ticket for "it runs" (as `app`, no sudo, systemd user service, safe to re-run), and it was crowding builder-ingest's lane (about 5 tickets against builder-web's 2–3). Same builder procedure, own lane, `gpt-oss:120b`. The deploy log moved to `/var/log/daily-briefing/`, so the agents can read whether an install worked | Remove `builder-ops` from `agents/`, `ops/dispatcher.sh` and `agents/openclaw/openclaw.json5`, and give its lane back to builder-ingest |
| 18 | **OpenClaw keeps Tool Search on, and the builders' first backup is `nemotron-3-ultra`** (was `gemini-2.5-flash`) | `gpt-oss:120b` sometimes writes its tool call as text instead of running it. Measured on 2026-10-14: right 7 of 9 times with Tool Search on, 2 of 8 with it off, so it stays on (the 7-tool limit still cuts the prompt from 46.8k to 31.3k chars). `nemotron-3-ultra` got the same task right 3 of 3 times, so the retry after a glitch runs on it. It is NVIDIA, so builders on a backup still never share the reviewer's family (Google) | `agents/openclaw/openclaw.json5` |
| 19 | **When all of an agent's models are rate-limited, only that agent pauses, and the human gets a ticket.** The dispatcher skips it for 15, 30, 60, then at most 120 minutes between tries; the other agents keep working. It files one `rate-limit` + `needs-human` issue, comments on each further try, and closes it when the agent runs again. The item it was on keeps its labels, and no failure is counted | A rate limit isn't the ticket's fault. Before this, two rate-limited runs parked the ticket as `needs-human`, and every other agent on the same provider was parked one by one. Pausing per agent, not per provider, needs no knowledge of how each provider counts its limits. Only the runtime's own error is read (OpenClaw's last model-attempt line, Hermes's result record), never tool output, because the app's Run now has a rate limit and its code and tests mention 429. Tested on 7 sample errors on 2026-10-14. Rule 6 (one open ticket per builder) still holds: a builder whose PR waits for a paused tester doesn't start a second ticket | `ops/dispatcher.sh` (rate limits section) |
| 20 | **Send-backs are counted per check: CI, test and review each allow 2, and the third by the same check goes to the human. A red CI is re-run once per commit before it counts** | One shared count of 3 let a flaky CI failure use up the budget that a reviewer's "this isn't what the ticket asked for" needs. The dispatcher counts each send-back as it happens: its own for CI, and a tester or reviewer run that leaves its PR at `changes-requested` (they are only woken on `needs-test` or `needs-review` PRs, so the label is theirs). All agents share one GitHub account, so the PR timeline can't tell who added the label. At most 6 fix runs per PR before a human looks | `ops/dispatcher.sh` (send-back counting), counts in `~/work/.dispatcher/sendbacks/` on the VM |

## Infra: move to AWS (2026-10-14)

| # | Decision | Why | To change |
|---|---|---|---|
| 6 | **The VM runs on the AWS Free plan, not Oracle Always Free** | Oracle's only Always Free Arm shape returned "Out of host capacity" on all 42 tries over ~6 hours (6 at 2 OCPU / 12 GB, 36 at 1 / 6). `us-sanjose-1` has one availability domain, so there was nowhere else to try. The brief names the AWS Free plan as plan B. We switched after hours rather than the brief's "a day" to protect the 5-day schedule. The account's credits last until 2027-01-02 | The Oracle Terraform is in git history (commit `1ee3b1b`) |
| 7 | **VM size: `m7i-flex.large`** (2 vCPU / 8 GB, x86) | The size the brief names for plan B, and on the Free plan's instance list. About $2.50/day of credits, so they cover the build week and the review week | `instance_type` in `infra/terraform.tfvars`. A stop and start resizes it (a new public IP; DuckDNS follows). `t3.small` makes credits last ~4x longer |
| 8 | **Own VPC, not the account's default VPC** | Works the same in any account, including one whose default VPC was deleted | `infra/main.tf` |
| 9 | **No Elastic IP.** The VM keeps the public IP it boots with | Attaching one after boot changes the IP while first boot is still downloading packages. A reboot keeps the IP; only a stop and start changes it, and the DuckDNS cron follows within 5 minutes | Add an `aws_eip` in `infra/main.tf` |

## Infra (2026-10-14)

| # | Decision | Why | To change |
|---|---|---|---|
| 1 | **SSH (port 22) is open to any address.** Login is by key only; Ubuntu cloud images turn passwords off | A home IP changes, and a narrow rule would lock us out | Set `ssh_allowed_cidr = "<your-ip>/32"` in `infra/terraform.tfvars`, then `terraform apply` |
| 2 | ~~VM size: 1 OCPU / 6 GB (Oracle A1.Flex, Arm)~~ **Replaced by #7** | Oracle had no capacity at either size | |
| 3 | **OpenClaw is installed system-wide by root** (`npm install -g`), not per user | The `agents` user can run it but can't modify or auto-update it, so the version stays pinned. Each user's state still lives in its own `~/.openclaw` | Change `openclaw_version` and re-run `first-boot.sh` on the VM |
| 4 | **Terraform never replaces the VM by itself.** A newer image or an edited `first-boot.sh` is ignored | Replacing the VM wipes the agents' state and logs. A rebuild has to be on purpose | `terraform apply -replace=aws_instance.vm` |
| 5 | **The app listens on `127.0.0.1:8000` and keeps its data in `/var/lib/daily-briefing/`** | Caddy forwards HTTPS to that port. The data folder is owned by `app` and closed to `agents`, so no agent can touch live data | Edit the Caddyfile and folder in `infra/first-boot.sh`, and the matching rule in `SPEC.md` |
